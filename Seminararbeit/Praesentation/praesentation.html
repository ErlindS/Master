Frühere Studien zeigen gute Ergebnisse gegen CUDA, lassen aber offen, welcher Portierungsschritt was bewirkt.

Stufe 1: Single-Source & Ausführungsmodell

sycl::queue q;                                   // wählt Gerät
float* A = sycl::malloc_shared<float>(n * n, q); // USM shared
float* B = sycl::malloc_shared<float>(n * n, q);
float* C = sycl::malloc_shared<float>(n * n, q);

q.parallel_for(sycl::range<2>{n, n}, [=](sycl::id<2> idx) {
  const std::size_t i = idx[0];
  const std::size_t j = idx[1];
  float sum = 0.0f;
  for (std::size_t k = 0; k < n; ++k)
    sum += A[i * n + k] * B[k * n + j];
  C[i * n + j] = sum;
}).wait();

Im Kernel nicht erlaubt: Ausnahmen, Rekursion, virtuelle Aufrufe, dynamischer Speicher.

  • Single-Source: Host- und Gerätecode als C++-Lambda in einer Datei.
  • Indexraum: Ein Work-Item je Element von C.
  • Asynchron: Einreichen in die Queue kehrt sofort zurück; Gerät wählt der Device Selector / Backend.
[06:25–07:40 · 1:15] Kernidee von Stufe 1: Kein eigenes .cu/.cl nötig, Kernel ist ein C++-Lambda. Der Compiler erzeugt für die angegebenen Ziel-Backends Gerätecode; AdaptiveCpp generiert eine gemeinsame IR für JIT zur Laufzeit.

Speichermodell: USM & Buffer

USM shared (Stufe 1)

Ein Zeiger für Host und Gerät; Laufzeit verschiebt automatisch – bequem, aber Transfer unsichtbar.

USM device + Events (Stufe 2)

Daten im Gerätespeicher, Kopien explizit; Events steuern den DAG auf out-of-order-Queues.

Buffer + Accessoren (Stufe 2b)

Abstrakte Kapselung mit Zugriffsmodus; Laufzeit leitet Kopien und Abhängigkeiten selbst ab.

[07:40–08:45 · 1:05] Graue Elemente sind aus Stufe 1 bekannt, schwarz/rot sind neu. Out-of-order-Queue erlaubt gleichzeitige Kopie A und Kopie B. Daneben existiert noch USM host für direkten Buszugriff.

Antworten auf F1 und F2

F1 · Konzepte

Herstellerbindung und mehrfache Codebasen löst schon Stufe 1 durch Single-Source in Standard-C++ und Backends (auf einem Rechner sogar eine gemeinsame ausführbare Datei für CPU und GPU).

Abstraktion vs. Kontrolle entschärft der gestufte Einstieg: USM shared reicht zum Start; USM device, Events, Work-Groups und lokaler Speicher geben schrittweise Kontrolle zurück. Buffer sparen Abhängigkeitsangaben, kosten aber bis zu 64 % Laufzeit.

F2 · Performance-Portabilität

Funktional ist jede Stufe portabel, Leistung entsteht nicht von selbst: Kachelgrößen und Optimierungen bleiben geräteabhängig, Stufe 5 macht dies aber handhabbar.

Gegenüber nativem CUDA erreicht SYCL ohne lokalen Speicher und beim einfachen Stencil 81–108 %. Abstände entstehen bei der Codeerzeugung für lokalen Speicher/Barrieren (69–80 %) und Gleitkomma-Atomics (bis hinab zu 5 % auf der H100).

Grenzen: 3 Kernel · GPUs nur eines Herstellers · 1 Implementierung (DPC++) · PP gilt nur für diese Gerätemenge · CUDA-Matmul-Vergleich in getrennten nvcc-Läufen (13.4 / 12.8) · kein nativer CPU-OpenMP/BLAS-Vergleich · Host-Zeitmessung enthält Auftragsstart.
