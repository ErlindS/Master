Für Amd bräuchte man statts Cuda nämlich HIP 

=> Das ist jetzt Mies, aber Hilfe ist vorort und heißt SYCL (Das Wort Sycl wird groß eingeblendet.) Sycl ist ein zunächst ein Standard der Khronos Group, welche erlaubt heterogenen Code zu schreiben. (Das Bild wird gefixed und jetzt steht da QuellCode -> Sycl-Implementierung (jetzt zwei Pfeile von Sycl zu Cuda und AMD und Intel und CPU))

Heterogen heißt in diesem Fall unterschiedlichen und ist das Gegenteil von Homogen. Also man kann den selben Code schreiben, aber für unterschiedliche Grafikkarten. Es existieren zwei bekanntere implementierungen ein mal adaptive Cpp von Heidelberg und einmal DPP von Intel. die Implementierung unterscheiden sich leicht, aber erfüllen beide den Standard. Der Anwendungsfall für Sycl ist also für Großrechenzentren ausgelegt.

8 Minuten Konzepte (Stufe 1-5)

Stufe 1

In den folgenden Minuten werde ich euch die unterschiedlichen Konzepte vorstellen und was das eigentlich Sycl zu hat. Dabei ziehe ich immer die Matrizenmultiplikation als Beispiel ran.

Die erste Stufe ist die minimal invasivste Sufte meistens hat man ein Program und darin legt man eine Queue an. Was eine Queue ist kennt ihr vielleicht aus Algorithmen und Datenstrukturen. In diese Queue wird meist ein Work-Item angelegt oder auch ein Kernel. Dabei muss man jetzt auch von einem Host und einem Gerät unterscheiden. Ein host wird meistens die Instanz sein, die das Program ausführt und diese delegiert den Kernel einem Gerät. Wenn ein Kernel ein Gerät erreicht erhält, ist das ein Work-Item in einem Indexraum. 

Weil Konzepte meist sinnvoll sind, sind zusätzliche Beispiele auch noch hilfreich. An dieser Stelle könnt, Seht ihr den Code für die Stufe 1. 

Stufe 2

Host und Gerät besitzen häufig getrennte Speicher, etwa den Arbeitsspeicher

des Rechners und den Grafikspeicher einer GPU\@. SYCL bietet zwei Wege, Daten

zwischen ihnen zu verwalten: Unified Shared Memory (USM) und Buffer.

Buffer kann man sich wie einen Container vorstellen, welcher Endpunkte uzr Verfügung stellt. Geräte können dann zum Beispiel diese Daten anfragen, wenn man damit gerechnet werden sollte. 

Unified Shared memory funktioniert eher wie ein Pointer. Die konkrete Funktionsweise ist, dann vom Modi abhängig, denn es gibt zwei. Die zwei Modi sind Device allocation und Shared allocation. Bei der Shared allocation werden Daten automatisch hin und her kopiert. bei der Device allocation müssen Daten explizit rüberkopiert werden.
